# API ядра: класс SandWorld (C++ GDExtension)

`SandWorld extends RefCounted`. Его создаёт GDScript: `var world := SandWorld.new()`.
Координаты задаются в клетках, (0,0) — левый верхний угол, y растёт вниз.

## Инициализация

| Метод | Описание |
|---|---|
| `load_materials(data: Dictionary) -> bool` | Разобранный `materials.json`. Возвращает false и пишет `push_error` при ошибке схемы |
| `load_reactions(data: Dictionary) -> bool` | Разобранный `reactions.json`. Вызывается после `load_materials` |
| `setup(width: int, height: int) -> void` | Создаёт сетку, заполненную air с температурой `ambient_temp`. Повторный вызов пересоздаёт её |
| `get_width() -> int`, `get_height() -> int` | |
| `get_material_count() -> int` | |
| `get_material_info(id: int) -> Dictionary` | `{id, name, category, state, desc, color: Color, hidden}` — для палитры |
| `find_material(str_id: String) -> int` | −1, если такого нет |
| `get_thermal_time_scale() / set_thermal_time_scale(s: float)` | Масштаб тепла. По умолчанию берётся из materials.json, метод нужен для тестов |
| `count_material(id: int) -> int`, `get_mean_temp(id: int) -> float` | Для тестов и статистики |

`get_material_info` возвращает также `str_id` (строковый id из JSON).

**Как масштабируется энергия.** Мощности (decay_heat, тепло горения, теплопередача) умножаются
на `thermal_time_scale × heat_multiplier`. Разовые энергии (деление, реакции, взрыв) — только
на `heat_multiplier`. Поэтому `fission_energy` задаётся в единицах Дж на деление в масштабе клетки:
в клетке U-235 всего 2.2 Дж/К, рабочие значения — от 3 до 100 Дж.
Для движения край сетки — стена, для тепла — воздух при ambient.

## Симуляция

| Метод | Описание |
|---|---|
| `step(delta: float) -> void` | Продвигает мир на `delta` реальных секунд. Внутри фиксированный шаг 1/60 с с аккумулятором, не больше 4 шагов за вызов. На паузе не вызывается |
| `step_once() -> void` | Ровно один фиксированный шаг (кнопка «шаг кадра») |
| `set_heat_multiplier(m: float)` | 1.0 обычно, 3.0 — «быстрый разогрев». Ускоряет только тепло: теплопередачу, фазовые переходы, нагрев от реакций и деления, decay_heat. Движение не трогает |
| `set_gravity(dir: Vector2)` | Нормализованное направление гравитации, по умолчанию (0,1). Учитывается в движении сыпучих, жидкостей и газов (газы — в противоположную сторону). Для v0.1 достаточно 8 направлений: ядро округляет к ближайшему |
| `set_ambient_temp(c: float)` | Температура air, которую мир держит на краях сетки (граница — бесконечный воздух) |
| `clear() -> void` | Всё обращается в air, нейтроны удаляются |

## Рисование

| Метод | Описание |
|---|---|
| `paint_circle(c: Vector2i, r: int, mat: int, mode: int)` | mode: 0 — только в air, 1 — заменять всё. Новые клетки получают `initial_temp` |
| `paint_line(a: Vector2i, b: Vector2i, r: int, mat: int, mode: int)` | Штрих между двумя точками, чтобы при быстром движении пальца не было разрывов |
| `erase_circle(c: Vector2i, r: int)` | Превращает клетки в air с температурой ambient |
| `heat_circle(c: Vector2i, r: int, watts: float, delta: float)` | Вливает (watts > 0) или забирает (< 0) энергию: watts на клетку × delta × heat_multiplier. Инструменты «Нагрев» и «Охлаждение» |
| `spawn_neutrons(c: Vector2i, r: int, count: int)` | Инструмент «Источник нейтронов» (быстрые нейтроны в случайных направлениях) |

## Чтение состояния

| Метод | Описание |
|---|---|
| `get_color_buffer(view: int) -> PackedByteArray` | RGBA8, ширина×высота×4, строки сверху вниз. view: 0 — обычный (с учётом glow и нейтронов поверх), 1 — тепловизор (шкала −50…3000 °C, логарифмическая выше 100), 2 — нейтроны и радиация (материалы приглушены, поток нейтронов яркий) |
| `get_cell(p: Vector2i) -> Dictionary` | `{mat: int, temp: float, name: String}` — для термометра под курсором |
| `get_stats() -> Dictionary` | `{step_ms: float, active_chunks: int, neutrons: int, fissions_per_sec: float, max_temp: float}` |

| Метод | Описание |

| `load_bytes(data: PackedByteArray) -> bool` | |

## Требования к производительности

- Сетка 320×180 при 50 % заполнения: `step_ms` ≤ 4 мс на Apple M-серии в release-сборке. На iPhone цель — 60 FPS.
- Чанки 64×64 со спящим режимом действуют для движения. Тепло считается везде, но чанк с почти
  ровной температурой (разброс < 0.05 К) и без движения тоже засыпает.
- До 20 000 нейтронов одновременно.

## Эталонный тест «кастрюля»

Это сцена headless-теста `tests/pot_test.gd`. Нагреватель (`heater`, fixed_temp 400 °C)
шириной 24 клетки. На нём стальное дно толщиной 2 клетки и стальные стенки, внутри вода
20×10 клеток при 20 °C, воздух 20 °C. Ожидаем:

1. Сталь у дна прогревается выше 100 °C раньше, чем вода в среднем дойдёт до 50 °C. Порядок как в реальности.
2. При `heat_multiplier = 1` первый пар появляется через 45–75 с, при 3 — через 15–25 с.
   Добиваемся этого подбором `thermal_time_scale` в materials.json.
3. Вода не превращается в пар целиком мгновенно, скрытая теплота работает.

## Дополнение v0.1.1: воздух, слои, источники

### Поле воздуха
Ядро хранит грубую сетку скоростей воздуха: одна ячейка поля покрывает 4×4 клетки мира, при 320×180
это 80×45. Каждый шаг поле считается как несжимаемая жидкость (stable fluids):
1. адвекция;
2. проекция давления, 10–20 итераций Якоби;
3. лёгкая вязкость.

Что двигает воздух:
- **Плавучесть.** Горячий воздух и газы легче окружающих и поднимаются (против гравитации).
  Сила пропорциональна (T − T среднего в окрестности) / (T + 273).
- **Взрывы.** Взрыв дает радиальный импульс и источник дивергенции, то есть ударную волну.
- **Вентиляторы** (поле `fan` у материала).
- **Твёрдые тела, порошки и жидкости** — препятствия: скорость в них равна 0, граница непроницаема.
  Ячейка поля считается твёрдой, если в её 4×4 клетках больше половины не газ и не air.

Что воздух двигает:
- газы, огонь и дым переносятся по полю с вероятностью ∝ |v| (поле `wind_coupling`, по умолчанию 1 для газов и огня);
- лёгкие порошки (пепел, снег, опилки) — с коэффициентом `wind_coupling` из материала;
- тепло: air и газы переносят температуру вместе со скоростью (конвекция по полю).

| Метод | Описание |
|---|---|
| `get_air_grid_size() -> Vector2i` | Размер поля, например 80×45 |
| `get_air_velocity() -> PackedFloat32Array` | vx, vy попарно, построчно сверху вниз, в клетках мира в секунду |
| `get_air_cell_scale() -> int` | 4 |
| `add_air_impulse(c: Vector2i, r: int, v: Vector2)` | Инструмент «Ветер»: проводишь пальцем, и воздух дует по направлению штриха |
| `set_air_enabled(on: bool)` | Для замеров производительности |

### Слои рендера
- `get_color_buffer(view)` теперь отдаёт air **прозрачным** (alpha 0) во всех видах. Газы рисуются
  полупрозрачными: пар, дым, водород дают alpha 0.35–0.7 в зависимости от плотности материала.
  Плотные газы вроде дыма менее прозрачны.
- `get_air_layer(view) -> PackedByteArray` — RGBA8 размером ширина×высота **поля воздуха**
  (80×45), только для воздуха. Фронт масштабирует его с линейной фильтрацией, поэтому слой
  выходит гладким, без пикселей.
  - view 0: тёплое марево над горячим воздухом, alpha ∝ (T − ambient), до 0.25; иначе прозрачно;
  - view 1: тепловизор по температуре воздуха, той же шкалой, что у материалов;
  - view 3: скорость воздуха, цвет по |v| от тёмно-синего через бирюзовый к белому, alpha 0.15–0.8.
- Новый вид **3 — «Потоки воздуха»**: в `get_color_buffer(3)` материалы приглушены (×0.45 яркости).
  Потоки поверх рисует фронт: трассеры, которые переносятся по `get_air_velocity()`.
- Производительность: `get_color_buffer` любого вида ≤ 0.5 мс на 320×180 (без pow/log на клетку,
  только LUT). Поле воздуха ≤ 1 мс на шаг.

### Источники и стоки
- Материал с полем `emit` выпускает заданный материал в соседние клетки air.
- Материал с полем `drain` поглощает соседние не-solid клетки (сток или «пустота»).
